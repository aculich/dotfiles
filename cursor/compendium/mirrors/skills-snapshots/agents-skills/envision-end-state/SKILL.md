# Envision end state

Compress options into a **shared future** that can be tested.

## When to Use

- Stakeholders verbally agree but imagine incompatible end states.
- Backcasting or roadmap work needs a crisp “there” before “path.”
- Risk reviews need explicit “what must remain true.”

## Workflow

1. **Protagonist** — pick one primary audience member from [clarify-audience-purpose](../clarify-audience-purpose/SKILL.md).
2. **Day-in-the-life sketch** — short narrative: what they do differently, what disappeared, what new friction exists (honesty clause).
3. **Mechanism links** — bullet causal chain from ship increments to the sketch (no magical jumps).
4. **Precursors** — what must be true in 30 / 90 days for the narrative to remain plausible?
5. **Falsifiers** — two signals that would kill or pivot the vision early.
6. **Risks** — include organizational, not only technical.
7. **Next**: pass narrative + risks to [converge-articulate](../converge-articulate/SKILL.md).

## Principles

- **Vivid constraint**: name concrete artifacts (screens, SLAs, dollars, clauses).
- Futures are hypotheses; tie them to **observables** (per backcasting and evaluation sources in repo research).
- If evidence is missing, label paragraphs as speculative—do not launder guesses as research.
